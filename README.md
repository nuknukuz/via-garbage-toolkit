# VIA Garbage Toolkit

Комплект инструментов для ускорения разметки bounding box'ов в **VIA 2.x** (VGG Image Annotator) на сериях аэрофотоснимков с БПЛА, где соседние кадры показывают одну и ту же сцену с небольшими изменениями ракурса.

Пользовательская инструкция (установка, ежедневный цикл, горячие клавиши, траблшутинг) — в [USAGE.md](USAGE.md).

## Состав

| Файл | Назначение |
|---|---|
| `via_group_transform.js` | Расширение VIA: модальные трансформации выделенных боксов в стиле Blender (G/S/R, рамка выделения B, 3D-наклоны) |
| `via_propagate.py` | Полуавтоматический перенос разметки между кадрами: кластеризация пака, выбор кадров-доноров, перенос боксов по гомографиям |
| `patch_via.py` | Однострочный установщик: подключает расширение к `via.html` (обе сборки — с внешним `via.js` и однофайловую) |
| `tests/` | Тесты: Node (JS, на заглушке VIA) и Python (чистые функции, без OpenCV) |

## Логика решения (что и почему)

Задача выросла из ручного сценария «A → C → на следующий кадр → V → подогнать каждый бокс руками». Итерации:

1. **Групповые трансформации (JS v1).** Линейный перенос группы боксов, поворот центров вокруг общего центра масс, «повороты вокруг осей в плоскости кадра» (перспективный keystone). Принципиальное ограничение: формат `rect` в VIA — axis-aligned, поэтому трансформируются центры и размеры, а сами боксы никогда не поворачиваются.
2. **Автоперенос (PY v1).** Гомография между соседними кадрами (ORB + MAGSAC/RANSAC, fallback на частично-аффинную), углы боксов прогоняются через H и снова приводятся к axis-aligned bbox.
3. **Словарь признаков (PY v3).** Вместо матчингов на каждую пару — O(n) сигнатур (эскиз 48×27 + HSV-гистограмма + кэш ORB-дескрипторов). Кластеры режутся по словарю; донор выбирается по максимуму совпадений дескрипторов; гомография считается один раз для выбранной пары из кэша.
4. **Двухстадийный цикл (PY v4/v4.1).** `--plan`: авто-кластеры (разрыв нумерации / мало совпадений / скачок сигнатуры) с интерактивным подтверждением и ручным вводом границ → предложение 2–5 кадров под ручную разметку (медоид + жадное max-min покрытие по сигнатурам + проверка покрытия дескрипторами) → файл плана. `--use-plan`: цели = все кадры кластеров кроме доноров, перенос на них. Резерв: `--clusters` + `--donors` без файла плана.
5. **Blender-клавиши (JS v2.x).** Модальные G/S/R/B; клавиши по `e.code` (не зависит от раскладки RU/EN — это была реальная найденная бага); собственное состояние выделения `GT_SEL`, не зависящее от внутренних флагов VIA; `Z` — откат GT-операции (алиас — `U`); штатный `X` вне режимов заглушен (сбивал с толку), `X/Y` работают как выбор оси внутри режимов.
6. **Координаты мыши без `_via_canvas_scale` (JS v2.3).** Рамка B хит-тестит боксы прямо в canvas-пространстве `_via_canvas_regions` (в нём VIA и рисует), а масштаб canvas→image для трансформаций выводится эмпирически — медиана отношений `width` в парах «метаданные ↔ canvas-регион». Это чинит симптомы «B выделяет не то / всё подряд» и «двигаются все боксы» при зуме или авто-масштабе больших кадров (старая `evXY` гадала по `_via_canvas_scale` и ошибалась вдвое по степени).

## Архитектура `via_group_transform.js`

- **Чистая геометрия** (`segRect`, `boxCaptured`, `xfGrab`, `xfScale`, `xfRot`, `xfTiltV/H`) — без DOM, экспортируется через `module.exports` для тестов в Node.
- **Модальный движок**: `MODAL = {type, idx, snap, pivot, start, axis, individual, R}`. Каждый `mousemove` считает трансформацию **от исходного снимка** `snap`, а не накапливает — нет дрейфа и погрешностей. ЛКМ/Enter — применить, Esc/ПКМ/Z — откат к снимку.
- **Координаты**: `canvasMouse` (client→canvas через `getBoundingClientRect` и backing store), `canvasToImageScale` (эмпирический R), `canvasBoxes` (боксы в canvas-пространстве для рамки). `_via_canvas_scale` не используется вообще.
- **Точки интеграции с VIA** (все через `typeof`-стражи, переживает вариации версий 2.x): `_via_img_metadata`, `_via_image_id`, `_via_canvas_regions[i]` (флаги `is_user_selected` и canvas-координаты), `_via_load_canvas_regions()`, `_via_redraw_reg_canvas()`, `show_message()`.
- **Выделение**: приоритет у штатного выделения VIA; своё `GT_SEL` (ставится рамкой B) — резерв. `Shift+B` дособирает к объединению обоих. Esc снимает GT-выделение.
- **Как дорабатывать**: новая клавиша = `case` в `onKeydown` + xf-функция; чувствительность и шаги — в `CFG` в начале файла; таблица физических клавиш — `CODE2KEY`.

## Архитектура `via_propagate.py`

- `build_dictionary` — один проход по кадрам: сигнатура (эскиз z-нормированный 48×27, HSV-гистограмма 18×8) + ORB-кэш (`kp`, `des`, масштаб `s`).
- `cut_clusters` — резка рёбер: разрыв нумерации, `good_matches < --min-edge-matches`, скачок `d_sig` (median + `--cut-k`·MAD или `--cut-abs`).
- `suggest_donors` — медоид + жадное max-min покрытие в пространстве сигнатур; `coverage_check` до-предлагает слабо покрытые кадры.
- `pick_donor` — max `good_matches` внутри кластера (при равенстве — ближайший кадр).
- `estimate_H_cached` — MAGSAC → `estimateAffinePartial2D`; гейты `--min-inliers`, `--min-inlier-ratio`; `unscale_H` пересчитывает H в полное разрешение при разных масштабах.
- `warp_rect` — углы через H → axis-aligned bbox, клиппинг по границам, отбраковка при <25% сохранившейся площади.
- План — JSON-файл состояния (границы кластеров + доноры); применение переживает перезапуск терминала.

## Тесты

```bash
node tests/test_via_group_transform.js      # 26 проверок на заглушке VIA (только node)
python tests/test_via_propagate.py          # 16 тестов чистых функций (нужен numpy; cv2 НЕ нужен)
```

JS-тесты покрывают: геометрию рамки выделения (включая «крошечная рамка внутри огромного бокса»), осевые ограничения G/S, общий vs индивидуальный центр масштаба, семантику Z/X/Y вне режимов и внутри, русскую раскладку (`key='п'` + `code='KeyG'`), приоритет штатного выделения над `GT_SEL`, Shift+B при потерянных флагах VIA, работу рамки и переноса при зуме (canvas = image ×2, мусорный `_via_canvas_scale`), предупреждение «выделены ВСЕ боксы».

## Ограничения и нюансы

- Только `rect`-регионы; остальные формы пропускаются.
- `R,R` — ровно 90° (обмен w/h): произвольный поворот одного бокса несовместим с axis-aligned форматом.
- Откат (`Z`/`U`) одноуровневый: отменяет последнюю GT-операцию на текущей картинке.
- Гомография предполагает примерно планарную сцену; на высоких кучах возможны смещения — дожимка вручную через G/S/R.
- Перенос **заменяет** разметку целевого кадра; входной JSON скрипт никогда не меняет (пишет `--out`).
- Расширение работает только с локальной копией `via.html`, не с онлайн-версией на сайте VGG.
